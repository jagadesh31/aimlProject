We did not only do post-processing

Present the project as four contributions that form one continuous SER system on MELD audio.

Do not say: “Our novelty is only smoothing labels.”
Say this:
“We built an end-to-end Continuous Speech Emotion Recognition system for conversational audio. It includes data preparation on MELD, acoustic modeling, dense window-level recognition, temporal structuring into stable regions and transitions, and two evaluation modes — standard utterance classification and continuous window-to-utterance scoring.”

1 Conversational audio SER pipeline on MELD

Public MELD CSVs only give text + labels. We use the official raw clips, extract mono 16 kHz WAV, map each row to diaX_uttY.wav, and train/evaluate on speech audio only.

Files: prepare_meld.py, dataset.py, data/meld/audio/

2 Acoustic model for 7-class emotion

Log-mel + delta + delta-delta features → CNN (local spectral patterns) → BiLSTM (temporal context) → 7 emotions. Training choices matter: clip length handling, class imbalance, checkpoint selection. Utterance test accuracy improved from earlier ~34% to ~49%.

Files: features.py, model.py, train.py, evaluate.py

3 Continuous-in-time recognition design

This is method design, not a side script. We redefine inference as dense prediction: 2-second windows, 1-second hop, over a full dialogue stream (stitched turns). That is what makes SER continuous.

Files: features.sliding_windows, infer_timeline.predict_windows, stitch_dialogue

4 Temporal emotion structure + continuous evaluation

Window outputs are structured into stable emotion regions and named transitions (interpretable timeline). We also score continuous predictions against MELD gold turns by majority of windows inside each utterance — so continuous SER is evaluated, not only drawn.

Files: temporal_tracking.py, continuous_eval.py, evaluate_continuous.py

If mam says “isn’t contribution 4 just post-processing?”

“Contribution 4 is one module. The project contribution is the full continuous SER stack: data-to-model pipeline, continuous window recognition, temporal structure, and dual evaluation. Post-processing alone would not need MELD audio training or window-level modeling.”
